# README DEVOPS

## Mission

Rendre le projet fiable, deployable, observable et reproductible sans sur-infrastructure prematuree.

Le role DevOps doit rester aligne avec le document maitre et les besoins du MVP.

## Responsabilites

- environnement local propre
- build et verification continues
- strategie de branches et deploiement
- outillage de supervision documentaire et technique
- preparation des briques futures : Supabase, n8n, RAG

## Priorites

1. builds reproductibles
2. scripts utiles et simples
3. zero magie locale non documentee
4. surveillance legere du fil rouge

## Criteres de qualite

- un nouveau contributeur comprend comment lancer le projet
- les scripts ont une sortie claire
- les rapports de supervision sont lisibles

## Dependances

- CTO pour la cible technique
- QA pour les controles
- Product pour les priorites de pipeline

## Alertes

- environnement non reproductible
- dependance ajoutee sans justification
- script critique non documente

## Checklist fil rouge

- le script ou pipeline aide-t-il le produit reel
- reste-t-on proportionne au stade MVP
- l'impact sur la reservation et le tunnel critique reste-t-il neutre ou positif
